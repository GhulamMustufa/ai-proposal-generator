# API Documentation

The NestJS backend (`apps/api`) provides RESTful endpoints, Server-Sent Events (SSE) for real-time status updates, and handles third-party webhooks. It is separated into domain-specific controllers.

## Base URL
Local development: `http://localhost:3001`
Production: `(Insert Production URL)`

## Authentication
All protected routes require a valid Clerk JWT passed in the `Authorization` header:
```
Authorization: Bearer <clerk_token>
```
This is enforced globally using the `ClerkAuthGuard`.

---

## Proposals Module (`proposals.controller.ts`)

### `GET /api/proposals/history`
Returns all previous applications/proposals generated by the user.

### `POST /api/proposals/enqueue`
Enqueues a background task to generate a proposal or cold email.

**Security**: 
- Protected by `ClerkAuthGuard`.
- Protected by `@Throttle` limits.
- Enforces Freemium Paywall (`generationsCount`).

**Response**: `202 Accepted`

### `POST /api/proposals/generate`
Synchronous endpoint to generate a proposal immediately, leveraging an SSE stream or returning raw JSON if streaming is not requested.

### `GET /api/proposals/status/:userId`
Server-Sent Events (SSE) endpoint to listen for background job completion. The Next.js frontend connects to this `EventSource` to receive chunked text generation dynamically.

**Event Stream Output**:
```json
{
  "data": {
    "userId": "user_2bX...",
    "jobId": "uuid-optional",
    "status": "generated",
    "generatedText": "Dear Hiring Manager..."
  }
}
```

### `GET /api/proposals/:id/pdf`
> [!CAUTION]
> **DoS Vulnerability**: This endpoint converts the generated HTML proposal to a PDF using Puppeteer and streams the raw buffer back as a download. It runs *synchronously* in the request thread. If abused, spinning up multiple headless Chromium browsers will cause Node.js Out-Of-Memory (OOM) crashes.

## Profile & Personas Module (`profile.controller.ts`)

### `GET /api/profile` & `GET /api/profile/plan`
Fetches user data and billing status.

### `PUT /api/profile/api-keys`
Allows users to save their own OpenAI keys to bypass platform limits. (Note: These are currently stored in plaintext in the DB).

## Billing Module (Lemon Squeezy)

### `POST /api/billing/webhook`
Receives asynchronous webhook events from Lemon Squeezy to provision user accounts. Validates the X-Signature header using crypto SHA-256 HMAC against the `LEMON_SQUEEZY_WEBHOOK_SECRET`.

### `GET /api/billing/checkout`
Returns a secure, hosted checkout URL for the user to upgrade to Pro.
